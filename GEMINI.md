# Project Instructions: The Kriwils

## Git Conventions
All commit messages must follow the semantic commit format:
- `feat`: Menambahkan fitur baru.
- `fix`: Memperbaiki bug.
- `docs`: Mengubah dokumentasi.
- `style`: Perubahan formatting, spasi, dll (tidak mengubah logika).
- `refactor`: Perubahan kode yang tidak menambah fitur.
- `test`: Menambahkan atau memperbaiki pengujian.
- `chore`: Tugas rutin (build, dependency, dll)

Format: `<type>: <description>` (e.g., `feat: Add navigation menu`)

## Communication & Clarification
- **Mandate:** ALWAYS ask the user for clarification before proceeding if any part of a request, task, or proposed change is even remotely unclear or underspecified. Do not make assumptions, and prioritize safety through verification.
- **Strict Mode:** If a task could be interpreted in multiple ways, or if the impact of a command is not explicitly described by the user, you MUST pause and ask for confirmation first.
